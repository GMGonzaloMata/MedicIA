# Validación: Resumen clínico

1. Ejecutar el proyecto unitario de Vitest con `tests/unit/app/doctor-overview.test.tsx`, `tests/unit/app/clinic-header-navigation.test.tsx` y `tests/unit/modules/studies/application/get-doctor-overview.test.ts`. Verificar límites del caso de uso, consultas por contexto, filas, vacíos, estado de error y roles sin resumen. Aislar el entorno antes de cargar la configuración de prueba.
2. Solo en una base de pruebas descartable y separada de la demo, ejecutar `npm run test:integration -- tests/integration/study-storage/doctor-overview.test.ts`. El runner puede truncar tablas. El caso integrado muestra 3 pacientes y 7 estudios autorizados, con 5 filas. Debe excluir otros médicos, otra clínica, vínculos no vigentes y pacientes pendientes/revocados. Tras terminar una asignación, desaparecen sus estudios y se recalculan los totales.
3. Con datos sintéticos e instancia aislada, abrir Inicio como médico, vínculo doble, paciente y administrador. En escritorio, tablet y móvil (1440/768/375 px) y ambas apariencias, verificar lectura, envoltura de texto, foco y apertura real del visor. Contrastar estados 0/0 y 1/0. Probar enlaces existentes de paciente/administrador y los labels/destinos de la barra lateral.
4. Antes de integrar, ejecutar `npm run check` y `npm run test:e2e` con el aislamiento del proyecto y la base descartable. No correr estos comandos en la base interactiva ni en el servidor usado por la demo.
